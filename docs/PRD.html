循证：高校形成性作业反馈智能体 · 精简 PRD

版本 1.0 / 2026-11-26 / 交互原型与验证方案，不宣称生产模型效果

1. 问题、用户与证据

目标用户：教授本科《研究方法导论》的课程负责人，负责多班级文献综述练习的量规与最终反馈。助教可整理材料，课程负责人对反馈负责。一次只解决“收齐一批作业后，依据同一标准完成可追溯反馈”这一任务。首期只做形成性文字作业，不做终结性考试。

任务假设：一个班约 40 人，每两周一次短文练习；教师重复打开文件、找问题、对照量规、撰写建议，并担心助教标准不一。以上人数与频率是待验证的产品假设，不是访谈结论。试点前访谈 6 名课程负责人、4 名助教，现场观察 3 次批阅，取得脱敏计时记录；核实其中有多少工作能被辅助、哪些判断不能交给系统。

可核验依据：Jisc 的高校评价与反馈指南指出，评价和反馈占据师生工作量的重要部分，也讨论共享评语对批阅一致性的帮助。Holt、Sun、Davies（2024）的一所英国高校研究发现，学生对反馈的期望与教师批阅工时安排之间存在张力。这些资料支持问题存在，不证明中国高校用户愿意使用本产品，也不支持任何具体节省比例。

- Jisc — Principles of good assessment and feedback

- Holt et al. 2024 — Assessment feedback: What do students want and need?

用户期望：“让我快速找到需要我判断的地方，知道建议从何而来，能随时改，而不是逐份检查一段看起来都对的 AI 评语。”

2. 为什么需要 Agent

聊天模型可以写单份评语；本场景还需要跨文件保持标准、调用文档解析和量规检索、绑定证据、执行约束检查、暂停等待确认、局部重试并保存状态。价值在于带状态的多步工具编排与异常处理。确定性的文件格式、分数求和、权限和发布门禁由规则实现，文本证据对齐与反馈生成才交给模型。不声称一切都“非 Agent 不可”；若教师每次只有一份标准文本，简单表单足够，无需完整编排。

生产链路：读取任务配置 → 解析和匿名化 → 校验量规 → 按作业并行取证 → 依据量规生成结构化建议 → 验证引用与分值 → 风险分流 → 教师逐份确认 → 检查批次完整性 → 导出。任一步证据不足触发停止条件；不反复调用模型直到得到高置信度答案。工具最多两次解析重试，超限转人工。

3. 输入与统一处理

输入类别理想情况不完整 / 不规范情况统一方式
教学标准明确分档的量规与题目一句“看论证是否严谨”、缺分值或相互矛盾生成待确认草案；缺项提示；教师确认版本前不评分
学生作业可选中文本 PDF / DOCX 与作业编号拍照扫描、乱码、缺页、重名文件解析 / OCR + 页段锚点；哈希去重；低可读性标记；不可从文件名猜身份
批次清单 / 补证LMS 导出清单、教师核对的原文片段缺编号、同名、口头补充清单映射人工确认；补证记录来源与操作者，原件不可覆盖

统一中间结构：task_id、submission_id、anonymous_id、document_hash、rubric_version、page/paragraph、evidence_text、parse_quality、judgment、suggested_score、risk_flags、review_status、teacher_edit、audit_event。识别不出的段落保留空值，不补写。

Demo 边界：内置两份正常样例和一份扫描模糊样例；支持真实粘贴 / TXT 读取，但导入内容直接进入人工路径，不伪造模型结果。生产方案中的 PDF / DOCX / OCR、身份映射和模型均未实现。

4. P0 / P1 与非目标

P0：单课程单批次；确认一种量规；逐项证据定位；建议反馈；低置信度阻断；教师改分改评语与接管；批次状态；CSV 与审计记录导出。每条判断必须有来源或明确“无法判断”。批阅标准变更后，旧建议失效，须重算或人工复核。

P1：LMS 集成、助教协同与双人仲裁、跨批次标准漂移监测、学生反馈申诉、班级共性误区摘要、增量重跑、版本回滚。P0 不自动发学生消息，不写教务成绩，不判定作弊，不处理音视频作业、代码运行或终结性考试。Demo 仅覆盖量规 R2 单维度，不能宣称完整多维总评。

5. 核心功能模块（重点）

模块用户动作 / 输入系统职责与输出验收条件
任务与标准校准填题目、输入量规、确认版本提醒缺少分档与分值；生成草案但不自授权未确认标准不能执行；标准变化使旧建议失效
输入规范化上传作业与名单文本提取、编号、去重、身份映射、页面锚点解析失败可单份补传；不阻断其他作业，不丢原件
证据检索按量规维度查找作业证据输出原文片段与页段，不将学生内容作为指令每条实质判断可回原文；引用不存在则拦截
判断与约束验证模型生成结构化评分与反馈核验分数区间、证据覆盖、行动建议、禁止越权无依据不能给确定性结论；不从“缺失”自动扣分
教师确认台同屏查看原文与量规，修改并确认右侧建议、风险说明、可编辑分数与评语；接管事件留痕低风险仍需确认；高风险补证或接管前不能确认
批次交付检查完成数、导出仅导出已确认批次；附量规、证据和审计有待处理项不能导出完整批次；修改后重开确认
状态与恢复保存 / 中断后继续生产端持久化任务状态与幂等键；Demo 本地存储中断不生成重复作业；失败能定位到单份与步骤

关键确认页的优先级：左侧先读原文，再对照量规；右侧先看风险与理由，再编辑建议。置信度旁明确“演示值”，解释风险原因。不能以绿色状态代替阅读核对。接管后标签改为“人工接管中”，不把教师判断伪装成 AI 结论。

6. 端到端流程与责任

教师新建任务 → 载入或补齐量规 → 确认标准 → 智能体执行并显示工具级进度 → 按风险逐份复核 → 修改 / 补证 / 接管 → 确认本份 → 全部完成后查看结果 → 导出。工作台可直接体验异常路线。

AI：提取和整理、提出有来源的建议、指出不确定性。教师：选择标准、核实原文、判定争议、确认反馈与成绩、决定是否交付。系统：强制权限、校验、版本与审计。学生文本或附件中的命令不能获得工具权限。最终成绩、学术诚信及对学生的处分不得由本系统独立决定。

7. 异常与边界

触发条件系统行为兜底 / 恢复
量规缺失或分值冲突停在校准页，不执行评分教师补齐或确认草案；量规版本留痕
标准被修改当前批次旧建议失效重跑受影响维度；Demo 全部转人工
扫描模糊 / 缺页 / OCR 关键字段不清保留原文位置，禁止确定性评分教师补传 / 补证，或人工接管；不以缺证扣分
附件夹带“忽略量规”等指令仅作为原文，不进入系统指令或工具参数标记可疑内容；教师仍按原量规评价
身份无法匹配 / 重名不推断接收人，禁止发布教师映射清单；匿名批阅可继续
重复上传 / 重试以哈希和任务幂等键去重保留新版本、教师选定版本再评
模型超时 / 解析工具失败失败单份重试两次，其他作业保留进度转人工或稍后续跑；不生成假结果
引用不存在 / 建议分数越界约束验证失败，拦截草稿回证据检索一次；仍失败转人工
低置信度或评价器分歧风险标记，禁止自动确认教师复核；必要时第二位教师仲裁
教师修改已确认反馈撤销该份确认，关闭批次导出重新核对、重新确认，保留历史记录
尚有未确认作业结果按钮禁用，显示未处理数量回待办清单逐份处理
超长文件 / 不支持类型拒绝并明确限制，不静默截断转 TXT 或拆分；Demo TXT 限 1 MB
自定义文本或新量规Demo 不假装理解评分和反馈留空，交教师完成
离开页面 / 存储不可用Demo 提示恢复草稿；失败时保留会话重新导入；生产持久化到校内存储
隐私或越权访问生产按课程隔离，身份与正文分开撤销授权、审计；Demo 只在本浏览器存储，不宜导入真实学生隐私

正式产品要求：上传前脱敏提示；课程角色权限；传输 / 存储加密；默认作业与草稿保存 30 天（待学校确认），教师可提前删除；日志只存必要事件，禁止以原文训练模型；发布名单独立二次确认。Demo 无后端、登录与访问控制，不宣称实现这些能力。

8. 评测、指标与上线门槛

所有数值是拟定验收目标，尚无实测结果。质量门槛优先于省时目标。

类型指标定义初步门槛 / 观测方式
业务单份有效批阅时间：打开至确认的人工作业时间，含核验修改相对人工基线中位数减少 ≥30%；相同教师配对交叉实验
业务一次可用率：教师无需实质改写即可确认的草稿 / 全部草稿≥70%；先统一“实质改写”的标注口径
业务周留存：试点首次完成批次后下一次有作业时仍使用的教师比例观察 4 周；按有真实任务教师计算，避免假留存
AI引用正确率：能在对应原件找到且支持判断的引用 / 所有引用≥98%，另报严重捏造数，严重捏造必须为 0
AI与人工一致：建议分数与仲裁分差 ≤2（满分20）的比例≥90%；同时报 MAE 与加权 Kappa，按课程分层
AI约束满足率：范围、量规版本、必填引用、权限均通过的输出比例≥99%；未经教师确认发布事件为 0
AI高风险召回：被标风险的真实需人工样本 / 真实需人工样本≥95%；重点报告漏掉的不可辨识样本
过程转人工率：发生接管的作业 / 总作业；修改率和教师推翻率不盲目压低；按输入类型与原因分层，用于发现问题
AI校准质量：风险分层实际错误率，ECE / Brier风险越高错误率应单调上升；阈值仅用验证集拟合

评测集：在授权后收集至少 300 份脱敏作业，覆盖 3 门课程、不同完成水平与文本长度，另构建 60 个压力案例（缺页、模糊、提示注入、同义量规、反例和缺证）。合成异常不替代真实样本，单独报告结果。每份由 2 名有该课程经验的教师独立标出证据跨度、量规等级、分数、可行动反馈和需转人工标记；分歧交第三人仲裁，并保留分歧率。先做 30 份标注校准。

按课程 / 作业题目 / 学期分组切分 60% 开发、20% 验证、20% 锁定测试，禁止同一作业改写版跨集合；新学期留作外部验证。测试集不参与提示词调优，限定发布前使用次数，每次模型 / 量规变更跑回归并记录版本。不用模型自评充当唯一裁判，不把教师直接点“通过”当金标准。

灰度：先在 2 位教师中影子运行，只对比人工结果；达门槛后开放 10% 授权试点批次，再扩到 30%，最后扩大。始终保留逐份教师确认与人工入口。若出现未确认发布、严重错引或高风险漏判，立即停止生成新批次并回退上个版本；保留人工批阅。抽样复核已交付反馈并通知课程负责人。

回流：采集接管原因、修改前后差异、接受/拒绝与耗时；每周抽样盲审，区分标准问题、解析问题与推理问题，再进入开发集。测试集保持锁定。分别报告小样本置信区间与各课程分层表现，不用总体均值掩盖少数类型失败。

9. 交互验收

正常路线：工作台 → 新建 → 确认量规 → 四步执行日志 → 两份逐份修改并确认 → 结果 → 下载 CSV / JSON。

异常路线：工作台 → 异常体验 → 同上 → S-031 模糊证据触发阻断 → 输入核对过的补证或接管 → 人工填分数与反馈 → 确认 → 导出。所有样例均为虚构，置信度为预设值。完整点击脚本见演示说明。
